Store the raw LLM response alongside the parsed output so evals can catch parsing drift without re-running the model.

```python
from dataclasses import dataclass
from typing import Any
import json

@dataclass
class LLMResult:
    raw: str
    parsed: Any
    model: str
    latency_ms: int
    tokens_in: int
    tokens_out: int

async def call_llm(prompt: str, schema: dict) -> LLMResult:
    resp = await client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        response_format={"type": "json_schema", "json_schema": schema},
    )
    raw = resp.choices[0].message.content
    parsed = json.loads(raw)
    return LLMResult(
        raw=raw,
        parsed=parsed,
        model=resp.model,
        latency_ms=resp.usage.total_tokens * 2,  # rough proxy
        tokens_in=resp.usage.prompt_tokens,
        tokens_out=resp.usage.completion_tokens,
    )
```

- Raw responses let you audit parsing failures after the fact and rebuild eval datasets without burning tokens
- Attach model, latency, and token counts to every result so cost and quality regressions show up in dashboards automatically
- Never re-parse in the hot path; parse once, store both, and keep the hot path fast
