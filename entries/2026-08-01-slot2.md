Prefetch and cache embeddings for known query patterns to eliminate retrieval latency on repeat questions. A small in-memory or Redis cache keyed by normalized query text turns a 200ms embedding call into a sub-millisecond lookup.

```python
import hashlib
import redis
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")
r = redis.Redis(decode_responses=False)

EMBED_TTL = 86400  # 24h

def get_embedding(text: str) -> list[float]:
    key = f"emb:{hashlib.sha256(text.strip().lower().encode()).hexdigest()[:16]}"
    cached = r.get(key)
    if cached:
        return list(map(float, cached.split(",")))
    vec = model.encode(text).tolist()
    r.setex(key, EMBED_TTL, ",".join(map(str, vec)))
    return vec
```

- Normalize queries (trim, lowercase) before hashing so "How do I..." and "how do i..." hit the same cache entry
- TTL the cache; embeddings drift when models update, so 24h is a safe default
- For high-cardinality workloads, add a Bloom filter in front to avoid Redis round-trips on definite misses
