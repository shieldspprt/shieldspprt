Idempotent webhook handlers with a dedupe key prevent duplicate processing when retries arrive out of order.

```python
import hashlib
import time
from redis import Redis

redis = Redis(decode_responses=True)

def handle_webhook(payload: dict, signature: str) -> dict:
    dedupe_key = hashlib.sha256(
        f"{payload.get('event_id')}:{signature}".encode()
    ).hexdigest()

    if redis.set(f"webhook:{dedupe_key}", "1", nx=True, ex=86400):
        process_event(payload)
        return {"status": "processed"}

    return {"status": "duplicate", "dedupe_key": dedupe_key}
```

- Use a deterministic key derived from the event ID and signature so identical retries map to the same key.
- Set the key with `NX` (only if not exists) and a TTL that covers the provider's retry window.
- Return early on duplicates without re-running business logic.
