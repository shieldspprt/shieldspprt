Validate LLM tool-call arguments against a Zod schema before execution to catch malformed calls early and surface a typed error the agent can retry.

```ts
import { z } from "zod";

const ToolCallSchema = z.object({
  name: z.string(),
  arguments: z.record(z.unknown()),
});

function validateToolCall(raw: unknown) {
  const parsed = ToolCallSchema.safeParse(raw);
  if (!parsed.success) {
    throw new Error(`Invalid tool call: ${parsed.error.message}`);
  }
  return parsed.data;
}

// In the agent loop, before dispatching:
const call = validateToolCall(llmOutput.tool_call);
const result = await dispatch(call.name, call.arguments);
```

- Schema validation at the boundary prevents garbage from reaching your tools or database.
- `safeParse` gives you a typed error you can feed back to the model for a self-correction loop.
- Keep the schema in one place so the agent, the eval harness, and the API docs all stay in sync.
