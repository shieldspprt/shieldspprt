Eval-driven prompt iteration beats manual tuning. Treat prompts as code: write assertions for expected outputs, run them against a golden set, and iterate until pass rate stabilizes.

```typescript
interface TestCase {
  input: string;
  mustContain: string[];
  mustNotContain: string[];
}

async function evalPrompt(
  prompt: string,
  cases: TestCase[],
  run: (p: string, input: string) => Promise<string>
): Promise<{ pass: number; total: number; failures: TestCase[] }> {
  const failures: TestCase[] = [];
  for (const tc of cases) {
    const out = await run(prompt, tc.input);
    const ok = tc.mustContain.every((s) => out.includes(s)) &&
               tc.mustNotContain.every((s) => !out.includes(s));
    if (!ok) failures.push(tc);
  }
  return { pass: cases.length - failures.length, total: cases.length, failures };
}
```

- A small golden set (20-50 cases) catches regressions faster than vibe-checking in the playground.
- Failures become your next prompt edit targets — each cycle shrinks the failure list.
- Version the prompt alongside the eval so a rollback is a single git revert.
