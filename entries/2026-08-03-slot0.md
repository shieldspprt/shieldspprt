Use Postgres advisory locks to coordinate distributed agent workers without a separate lock service

```typescript
import { Pool } from "pg";

const pool = new Pool({ connectionString: process.env.DATABASE_URL });

async function withAdvisoryLock<T>(
  key: bigint,
  fn: () => Promise<T>
): Promise<T> {
  const client = await pool.connect();
  try {
    await client.query("SELECT pg_advisory_lock($1)", [key]);
    return await fn();
  } finally {
    await client.query("SELECT pg_advisory_unlock($1)", [key]);
    client.release();
  }
}

// Usage: serialize work per wallet so two agents don't sweep the same dust
await withAdvisoryLock(walletIdBigInt, async () => {
  const dust = await findDustAccounts(wallet);
  if (dust.length) await sweepDust(wallet, dust);
});
```

- Advisory locks are fast, don't require a table, and release automatically if the client disconnects
- Hash your coordination key (wallet id, job id) to a 64-bit integer to avoid collisions
- Prefer `pg_try_advisory_lock` for non-blocking attempts with immediate fallback
