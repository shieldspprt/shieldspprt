Backpressure on LLM token streams keeps memory bounded when the client cannot drain fast enough. A transform stream that pauses the upstream LLM reader when the high-water mark is hit prevents the server from buffering unbounded tokens.

```typescript
import { ReadableStream, TransformStream } from "node:stream/web";

function createBackpressureStream(highWaterMark = 64 * 1024) {
  let buffered = 0;
  return new TransformStream({
    transform(chunk, controller) {
      buffered += chunk.length;
      controller.enqueue(chunk);
      if (buffered >= highWaterMark) {
        controller.signal.reason = "backpressure";
      }
    },
    flush(controller) {
      buffered = 0;
    },
  });
}

async function streamLLMWithBackpressure(response: Response) {
  const reader = response.body!.getReader();
  const stream = new ReadableStream({
    async start(controller) {
      while (true) {
        const { done, value } = await reader.read();
        if (done) break;
        controller.enqueue(value);
        if (controller.desiredSize === null || controller.desiredSize <= 0) {
          await new Promise((r) => setTimeout(r, 50));
        }
      }
      controller.close();
    },
  });
  return stream.pipeThrough(createBackpressureStream());
}
```

- Backpressure signals let the LLM producer slow down instead of filling server memory.
- `ReadableStream`'s `desiredSize` is the standard signal; pause reads when it drops to zero or negative.
- A small high-water mark (64 KiB) keeps per-request memory predictable under load.
