Attach a unique request ID to every LLM call and log it alongside the prompt hash to correlate retries, timeouts, and cost in one query. This turns scattered provider logs into a single trace you can filter by user, model, or failure mode without changing your core loop.

```python
import uuid
import hashlib
import logging
from contextvars import ContextVar

request_id_var: ContextVar[str] = ContextVar("request_id", default="")

def log_llm_call(model: str, prompt: str, response: str, latency_ms: int, status: str):
    request_id = request_id_var.get() or str(uuid.uuid4())
    prompt_hash = hashlib.sha256(prompt.encode()).hexdigest()[:12]
    logging.info(
        "llm_call",
        extra={
            "request_id": request_id,
            "model": model,
            "prompt_hash": prompt_hash,
            "latency_ms": latency_ms,
            "status": status,
            "response_len": len(response),
        },
    )
```

- A stable request ID flows through retries and fallbacks so one failure appears as one row, not three.
- Prompt hashes let you aggregate cost and latency by semantic workload without storing full prompts.
- Structured logging with these fields makes it trivial to build a dashboard that shows p95 latency per model, retry rate per user, and cost per feature.
