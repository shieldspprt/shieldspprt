Rate limits are contracts not suggestions. When an upstream API returns 429 with a Retry-After header, respect it literally and add jitter. Blind exponential backoff without the header wastes quota and extends outages.

```python
import httpx
import asyncio
import random

async def fetch_with_retry(client: httpx.AsyncClient, url: str, max_retries: int = 3) -> httpx.Response:
    for attempt in range(max_retries):
        resp = await client.get(url)
        if resp.status_code != 429:
            return resp
        retry_after = resp.headers.get("Retry-After")
        if retry_after:
            delay = int(retry_after) + random.uniform(0, 1)
        else:
            delay = (2 ** attempt) + random.uniform(0, 1)
        await asyncio.sleep(delay)
    return resp
```

- Read Retry-After first, fall back to exponential backoff with jitter
- Cap max retries to prevent infinite loops on persistent failures
- Use a shared httpx.AsyncClient with connection pooling for throughput
