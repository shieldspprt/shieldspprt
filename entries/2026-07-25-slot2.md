## Validate Tool-Call Arguments Against a JSON Schema Before Execution

Let the model propose a tool call, then validate its arguments against a strict JSON schema before you dispatch it. This catches hallucinated parameters, wrong types, and missing required fields before they hit your database or external API.

```python
import jsonschema
from pydantic import BaseModel, ValidationError

TOOL_SCHEMAS = {
    "transfer_sol": {
        "type": "object",
        "properties": {
            "to": {"type": "string", "pattern": "^[1-9A-HJ-NP-Za-km-z]{32,44}$"},
            "amount_lamports": {"type": "integer", "minimum": 1},
        },
        "required": ["to", "amount_lamports"],
        "additionalProperties": False,
    },
}

def validate_tool_call(name: str, args: dict) -> tuple[bool, str]:
    schema = TOOL_SCHEMAS.get(name)
    if not schema:
        return False, f"Unknown tool: {name}"
    try:
        jsonschema.validate(args, schema)
        return True, ""
    except jsonschema.ValidationError as e:
        return False, f"Invalid args for {name}: {e.message}"

# Usage in your agent loop
ok, err = validate_tool_call(tool_name, tool_args)
if not ok:
    return ToolResult(error=err)  # feed back to model for retry
result = await dispatch(tool_name, tool_args)
```

- Define one canonical schema per tool and share it between the model (via function-calling definitions) and your validator.
- Reject invalid calls early and return the validation error to the model so it can self-correct in the next turn.
- Keep schemas strict: `additionalProperties: false`, regex for addresses, numeric bounds for amounts.
