Handle partial tool-call failures with compensating actions

When an agent issues multiple independent tool calls in parallel and one fails, do not roll back the successful ones. Instead, record the failure and issue a compensating action (retry, fallback, or explicit cleanup) while the successful results remain usable. This keeps the user-facing flow intact and avoids cascading rollbacks that waste tokens and latency.

```typescript
async function runWithCompensation(calls: ToolCall[]) {
  const results = await Promise.allSettled(calls.map(c => c.execute()));
  const successful = results.filter(r => r.status === 'fulfilled').map(r => r.value);
  const failed = results.filter(r => r.status === 'rejected').map(r => r.reason);

  if (failed.length > 0) {
    await Promise.all(failed.map(f => compensator.compensate(f)));
  }
  return successful;
}
```

- Use Promise.allSettled so one failure does not cancel the rest
- Design compensators (retry, fallback, cleanup) as first-class operations, not afterthoughts
- Keep the successful partial state so the user sees progress even when something fails
