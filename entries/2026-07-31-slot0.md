Fallback chains for LLM providers keep your app available when the primary goes down. Wrap every provider call in a retry loop that exhausts the chain before surfacing an error.

```python
from typing import Literal
from dataclasses import dataclass

Provider = Literal["openai", "anthropic", "gemini", "groq"]

@dataclass
class ProviderConfig:
    name: Provider
    model: str
    api_key: str
    base_url: str | None = None

CHAIN: list[ProviderConfig] = [
    ProviderConfig("openai", "gpt-4o-mini", "sk-..."),
    ProviderConfig("anthropic", "claude-3-5-haiku", "sk-ant-..."),
    ProviderConfig("groq", "llama-3.1-70b-versatile", "gsk_..."),
]

async def complete_with_fallback(messages: list[dict], chain: list[ProviderConfig]) -> str:
    last_err: Exception | None = None
    for cfg in chain:
        try:
            return await call_provider(cfg, messages)
        except Exception as e:
            last_err = e
            continue
    raise RuntimeError(f"All providers failed, last error: {last_err}")
```

- Rotate through a prioritized provider list so a single outage does not kill the request
- Keep the chain short (2 to 3 providers) to bound latency and cost variance
- Log every fallback so you can measure provider reliability and adjust ordering
