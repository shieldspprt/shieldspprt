A typed event bus lets you observe agent behavior without coupling instrumentation to business logic. Emit structured events at decision points (tool call, retry, fallback) and subscribe a logger or evaluator downstream.

```typescript
type AgentEvent =
  | { type: "tool.call"; name: string; args: unknown; requestId: string }
  | { type: "tool.result"; name: string; ok: boolean; latencyMs: number; requestId: string }
  | { type: "llm.call"; model: string; promptTokens: number; requestId: string }
  | { type: "llm.result"; model: string; completionTokens: number; requestId: string }
  | { type: "agent.fallback"; reason: string; requestId: string };

const bus = new EventTarget();

function emit<T extends AgentEvent>(e: T) {
  bus.dispatchEvent(new CustomEvent("agent", { detail: e }));
}

// In your agent loop
emit({ type: "tool.call", name: "search", args: { q: "solana" }, requestId: "req-1" });
const result = await search({ q: "solana" });
emit({ type: "tool.result", name: "search", ok: true, latencyMs: 120, requestId: "req-1" });
```

- Subscribers (logging, evals, dashboards) stay decoupled from the agent core
- Structured events make it trivial to build traces, compute latency percentiles, or detect fallback storms
- Adding a new observer never requires touching the agent code again
